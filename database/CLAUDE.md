# database/CLAUDE.md

Database conventions for this template. Read after the root `CLAUDE.md`.

## Folder layout

- `migrations/` — schema. Files generated by `php artisan make:migration` so timestamps are correct.
- `factories/` — model factories. `UserFactory` is the canonical example.
- `seeders/` — `DatabaseSeeder` is the entry; call other seeders from it.

## Migration conventions

- `declare(strict_types=1);` at the top.
- For audit columns (`created_by`, `updated_by`): use `$table->whoDidIt();` instead of hand-writing foreign keys — the macro is defined in `App\Mixins\WhoDidItMixin` and registered globally in `AppServiceProvider::configureMixins()`.
- Match Laravel's defaults for `id` (`bigIncrements`) and `timestamps` unless there's a real reason to deviate.

## Seeders

- `DatabaseSeeder` is intentionally minimal — most projects bootstrap with a `php artisan create:user` instead of seeded users. Real seeding belongs in project-specific seeders.
- If you need QA-friendly seeded users at multiple permission tiers, write a `QaSeeder` class and invoke it with `php artisan db:seed --class=QaSeeder` rather than auto-running on every fresh.
- Use factories from seeders — don't rebuild user data inline.

## Factories

- One factory per Model. `UserFactory` shows the canonical pattern with attribute states (`unverified`, etc.).
- `Hash::make()` for passwords — the User model's `booted()` will re-hash on save, but factories should still emit a real bcrypt so tests don't depend on the boot hook.

## Things to NOT do

- **Never run `migrate:fresh` against the dev DB without confirming.** It will wipe everything. `DB::prohibitDestructiveCommands` blocks it in prod but dev is fair game.
- **Don't add audit columns by hand.** Use `$table->whoDidIt()`. Consistency lets the `WhoDidIt` trait do the rest.
- **Don't seed test-tier data in `DatabaseSeeder`.** Keep it as a router to optional seeders so production seeding stays predictable.
